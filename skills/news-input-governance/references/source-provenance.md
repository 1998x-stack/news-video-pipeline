# 输入与证据：工程参考与验收规范

## 1. 定位和真相来源

- 对应模块：`src/news_video_pipeline/planner.py:read_input`
- 输入契约：原稿 UTF-8 TXT/MD/JSON；来源 URL（可选）；人工权利信息（不可自动推定）
- 成功产物：标题/字数/输入哈希/警告；未核实事实与权利清单
- 已实现边界：P0 仅支持用户本地输入，不提供自动联网采集、引用验证或版权许可裁定

## 2. 分阶段操作

### 1. 检查点 1
先核对文件扩展名、UTF-8 编码、3 MB 上限以及 JSON body 是否存在；原样保存输入哈希。
失败时必须保留可定位的文件/异常与运行条件，而不是跳过当前阶段。

### 2. 检查点 2
提取可识别标题并记录来源 URL、采集时间、发行主体；未知值必须写 unknown。
失败时必须保留可定位的文件/异常与运行条件，而不是跳过当前阶段。

### 3. 检查点 3
将逐项事实与文字证据分开登记；对政策、日期、数量、引语标记需要人工核验。
失败时必须保留可定位的文件/异常与运行条件，而不是跳过当前阶段。

### 4. 检查点 4
对版权、肖像、授权保留待审状态。技术处理不得产生发布批准。
失败时必须保留可定位的文件/异常与运行条件，而不是跳过当前阶段。

## 3. 验收门禁

- [ ] 不得联网假设输入来源权威；也不能补写未提供的新闻事实。
- [ ] 绝不因为缺少授权证明就默认为已获授权。
- [ ] 所有结论从文件或可核实的调用产物得出；若无证据，写 `unknown / manual_review_required`
- [ ] 输入、配置、工具版本、时间戳与产物哈希可供重放
- [ ] 回归测试可运行，新增逻辑具有非法输入、边界输入与正常输入测试

## 4. 失败处理

1. 不运行媒体管线后续阶段，先确认上游输入与契约。
2. 记录错误类型、输入路径、对应 Scene/Cue 或文件名（不要记录密钥）。
3. 如果是外部服务或许可不明确，不得自动回退为伪造内容、其他版权素材或 synthetic 配音。
4. 修复后重新执行校验，保留旧结果用于差异比对；不得把 `qa_passed` 等同于 `public_release_approved`。

## 5. 推荐调用

```bash
python skills/news-input-governance/scripts/audit_input.py examples/sample_news.md
```

详见 `docs/architecture.md` 与 `AGENTS.md`；任何 P1/P2 建议先形成提案，不自动声称功能已交付。
