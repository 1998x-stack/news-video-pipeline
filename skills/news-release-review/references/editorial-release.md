# 发布前人工签核：工程参考与验收规范

## 1. 定位和真相来源

- 对应模块：`src/news_video_pipeline/docs/roadmap.md,AGENTS.md`
- 输入契约：技术完成的视频包；内容/事实证据/授权/平台账号检查清单
- 成功产物：未通过时明确阻止发布；人工评估建议，不自动上传
- 已实现边界：仅提供发布前评估脚本与核验协议，无真实审核后台或自动发布 API

## 2. 分阶段操作

### 1. 检查点 1
分别确认来源、每一项核心事实、引语、图片、音色、肖像及音乐的使用权。
失败时必须保留可定位的文件/异常与运行条件，而不是跳过当前阶段。

### 2. 检查点 2
技术验收包括 manifest、timeline、SRT、MP4 及实际声音和字幕人工试听。
失败时必须保留可定位的文件/异常与运行条件，而不是跳过当前阶段。

### 3. 检查点 3
保留人类责任人的明确批准记录及批准对象的不可变哈希，批准不得从模型推理得出。
失败时必须保留可定位的文件/异常与运行条件，而不是跳过当前阶段。

### 4. 检查点 4
P2 发布器未实现，禁止模拟发布成功；任何平台授权和投稿需要单独显式操作。
失败时必须保留可定位的文件/异常与运行条件，而不是跳过当前阶段。

## 3. 验收门禁

- [ ] 不要凭技术 QA 或文字“已核验”就把 public_release_approved 改为 true。
- [ ] 证据缺失一律待审；不生成虚构引用或许可协议。
- [ ] 所有结论从文件或可核实的调用产物得出；若无证据，写 `unknown / manual_review_required`
- [ ] 输入、配置、工具版本、时间戳与产物哈希可供重放
- [ ] 回归测试可运行，新增逻辑具有非法输入、边界输入与正常输入测试

## 4. 失败处理

1. 不运行媒体管线后续阶段，先确认上游输入与契约。
2. 记录错误类型、输入路径、对应 Scene/Cue 或文件名（不要记录密钥）。
3. 如果是外部服务或许可不明确，不得自动回退为伪造内容、其他版权素材或 synthetic 配音。
4. 修复后重新执行校验，保留旧结果用于差异比对；不得把 `qa_passed` 等同于 `public_release_approved`。

## 5. 推荐调用

```bash
python skills/news-release-review/scripts/release_check.py outputs/<run-id>
```

详见 `docs/architecture.md` 与 `AGENTS.md`；任何 P1/P2 建议先形成提案，不自动声称功能已交付。
